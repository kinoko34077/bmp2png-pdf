# BMPからPNGへの変換とPDF作成ツール 設計書

- 作成日: 2026-10-09
- 状態: 設計承認済み
- 作成先: kinoko34077/bmp2png-pdf（候補名の空き確認済み、公開）

## 目的
既存のBMP一括変換ツールを拡張し、PNGの可逆圧縮レベルを選べるようにする。BMPをPNGに変換した後、ユーザーが指定した順序で画像をまとめた1つの複数ページPDFを作成する。最終配布物は、利用者がPythonやインターネットを用意しなくてもWindows上で動くデスクトップアプリケーションとする。

## 現在のプロジェクト
提供されたフォルダーには bmp_to_png_gui.py、requirements.txt、gui.bat がある。Tkinter GUIで、Pillowとtkinterdnd2を使用する。BMPのドラッグ＆ドロップまたはファイル選択、一覧表示、一括クリア、入力BMPと同じフォルダーへのPNG保存に対応している。現時点でこのフォルダーはGitリポジトリではない。

## 合意した機能と動作
- BMPのドラッグ＆ドロップ、ファイル選択、一覧クリア、一括変換、処理状況の表示を維持する。
- PNG圧縮レベルを0〜9で選べるようにし、初期値は6とする。PNGは可逆圧縮のため画質は劣化せず、値によってファイルサイズと処理時間のバランスが変わる。
- 上へ／下へ移動する操作を追加し、一覧の表示順を変更できるようにする。PDFのページ順は一覧の順番に従う。
- 先に各BMPをPNGに変換する。PNGは既存動作を保ち、元BMPと同じフォルダーに保存する。
- 変換で生成したPNGを入力順にまとめ、1つの複数ページPDFを作成する。BMPごとに別々のPDFは作らない。
- PDFの保存先は利用者が指定する。
- PDFは画像1枚につきA4の1ページとする。画像の縦横に合わせてページを縦または横にし、縦横比を維持してページ内に収め、切り抜きはしない。
- 変換に失敗した場合、成功済みPNGは残す。失敗内容を表示し、その実行では不完全なPDFを作らない。
- 画像変換とPDF作成は利用者のPC内で完結させる。

## 推奨構成と処理順序
既存のPython、Tkinter、Pillow、tkinterdnd2を継続利用する。A4ページのレイアウトに必要ならPDF生成用の依存ライブラリを追加する。ブラウザー、サーバー、クラウド処理は導入しない。GUIが処理の進行と結果表示を担当し、BMP→PNG変換とPDF組み立ては小さく独立した関数に分ける。
1. 一覧に表示されている順番でBMPを取得する。
2. 選択されたPNG圧縮レベルを使って、すべてのBMPを同じフォルダーのPNGへ変換する。
3. すべての変換が成功した場合に限り、生成したPNGを読み込み、同じ順番でA4複数ページPDFにまとめる。
4. PNGとPDFの保存先、および失敗があれば失敗内容をGUIに表示する。

## Windows向け配布
初回の配布対象は64-bit Windowsとする。PyInstallerで実行ファイルと必要ファイルをまとめ、インストーラーを使わないポータブル形式で配布する。利用者側ではPython、依存ライブラリの導入、ネット接続を不要にする。ビルドする側にはPythonの開発環境と依存パッケージが必要。ビルド自動化で成果物を作成し、GitHub Releaseやバイナリ配布はdevflowの公開ゲートに従って別途判断する。初回にはインストーラーを追加しない。

## 受け入れ条件
1. 既存のBMP選択、ドラッグ＆ドロップ、一覧クリア、PNG変換を利用できる。
2. PNG圧縮レベル0〜9を選べ、既定値6がPNGエンコードに適用される。
3. 入力画像を並び替えられ、表示順がPDFのページ順に反映される。
4. BMPごとに1つのPNGが元BMPと同じフォルダーに保存される。
5. 正常時は、生成されたPNGを元に画像1枚1ページのA4 PDFが1つ作られ、画像の向きと縦横比が保たれ、切り抜かれない。
6. 変換失敗を報告し、成功済みPNGを残し、不完全なPDFを作らない。
7. Windows向け配布アプリが、利用者側にPythonやネット接続がない環境で起動し、変換とPDF作成を行える。
8. 公開リポジトリに開発・ビルド手順を記載し、生成物やローカルPC固有のパスを含めない。

## 初回対象外
- BMP以外の入力形式。
- 画像1枚ごとのPDF作成。
- 画像編集、リサイズ、非可逆圧縮、OCR、クラウド処理。
- インストーラー、自動更新、コード署名、Windows以外のOS。
- ユーザーが選択していないライセンスの追加。
