# BMPからPNGへの変換とPDF作成ツール 設計書

- 作成日: 2026-10-09
- 更新日: 2026-10-09
- 状態: 設計承認済み（追加要件反映）
- リポジトリ: `kinoko34077/bmp2png-pdf`（public）

## 目的

既存のBMP一括変換ツールを拡張し、PNGの可逆圧縮レベルを指定できるようにする。BMPをPNGに変換した後、利用者が指定した順序で画像を1つの複数ページPDFにまとめる。最終的には、利用者側にPythonやネット接続を求めないWindowsデスクトップソフトとして配布する。

## 現在のプロジェクト

元フォルダーには `bmp_to_png_gui.py`、`requirements.txt`、`gui.bat` があり、Tkinter、Pillow、tkinterdnd2を使う。BMPのドラッグ＆ドロップ、ファイル選択、一覧表示、一括クリア、入力BMPと同じフォルダーへのPNG保存に対応している。公開リポジトリ `kinoko34077/bmp2png-pdf` はdevflow Bootstrapで作成済み。

## 機能と動作

- BMPのドラッグ＆ドロップ、ファイル選択、一覧クリア、一括変換、処理結果表示を維持する。
- 一覧はドラッグで並べ替えできる。選択項目を上／下へ移すボタンも用意し、一覧の順序を常に変換・PDFの順序として使う。
- PNG圧縮レベルは0〜9から選び、初期値は9（高圧縮）とする。PNGは可逆なので画質は変わらず、圧縮レベルにより処理時間と出力サイズが変わる。設定の永続化は初回対象外。
- BMPはまずPNGへ変換し、PNGを元BMPと同じフォルダーに保存する。
- PDF出力は「PDFにする」チェックボックスで任意に有効化する。チェック時に使うPDFファイル名の入力欄を画面に表示し、保存先は保存ダイアログで指定する。拡張子 `.pdf` は未入力なら自動で付ける。チェックを外した場合はPDFを作らず、PNG変換だけを行う。
- チェック時はすべてのBMPを先にPNGに変換する。全件成功後に、そのPNGを一覧順でまとめたPDFを1つだけ作る。BMP別のPDFは作らない。
- PDFは画像1枚につき1ページ。A4ページは画像の向きに合わせ、余白を確保して縦横比を維持したまま配置する。PNGをリサイズ／再サンプリングせず、画像ピクセルの解像度を維持する。PNGにDPI情報があればそれも尊重する。
- PDFを開いたときの表示設定に、ページ全体を表示する初期倍率（Fit）と単ページ表示を設定する。
- 変換失敗時は成功済みPNGを残し、失敗内容を示し、部分的なPDFは作らない。
- 処理はPC内で完結する。

## 推奨構成

Python、Tkinter、Pillow、tkinterdnd2を継続利用し、PDF生成にReportLab、PDFの初期表示メタデータ設定にpypdfを使う。変換とPDF生成はGUIから分離した関数にする。ネット接続、サーバー、クラウド処理は導入しない。

処理順:

1. 画面上の一覧順からBMP入力を取得する。
2. 選択圧縮レベルでPNGをすべて生成する。
3. PDFチェックがオフなら完了を表示する。
4. PDFチェックがオンなら、全PNG変換成功後に保存先を確定し、PNG群から1つのPDFを作る。PDFには一覧順で画像を配置し、ページ全体表示と単ページ表示のメタデータを加える。
5. 保存結果またはエラーを画面に示す。

## Windows向け配布

初回配布対象は64-bit Windows。PyInstallerでPythonランタイムと依存物をまとめたポータブル形式を作成する。利用者側はPythonやインターネットなしで使える。ビルドする側にはPython開発環境と依存パッケージが必要。まずone-folder配布を採用し、初回はインストーラー、自動更新、コード署名を含めない。Releaseやバイナリの公開はdevflowの現行ゲートに従って別途判断する。

## Issue掲載用の設計

### 今回の設計書

- PNG圧縮レベルは0〜9を選択可能とし、高圧縮の9を初期値とする。PNGは可逆圧縮。
- 入力BMPは一覧の並び順で変換する。並べ替えはドラッグ操作と上下移動ボタンの両方に対応する。
- 各BMPをまずPNGへ変換し、PNGは元BMPと同じ場所に作る。
- 「PDFにする」チェックボックスを追加する。チェック時にPDF名の入力欄を使い、保存先ダイアログで場所を選ぶ。未入力の拡張子 `.pdf` は補完する。チェックなしならPNGのみを作る。
- PDFは、全PNG変換が成功した場合に限り、一覧順で全画像を含む単一ファイルとして作る。BMPごとのPDFは作らない。
- PDFは画像1枚につき1ページのA4。ページ向きを画像に合わせ、縦横比を維持し、切り抜きやラスタ画像の再サンプリングをしない。PNGのDPI情報があれば尊重する。
- PDFの初期表示をページ全体が見えるFit、単ページ表示に設定する。
- 変換失敗時は成功済みPNGを残し、エラーを示し、PDFは生成しない。処理はローカルで完結。
- 技術構成はPython、Tkinter、Pillow、tkinterdnd2、ReportLab、pypdf。Windows x64向けにPyInstallerのone-folderポータブル版を作る。利用者側にPythonやネット接続は不要。
- 初回対象外: BMP以外の入力、個別PDF、画像編集や非可逆圧縮、OCR、クラウド、インストーラー、自動更新、署名、他OS、未選択ライセンス。
- GitHub Releaseやバイナリ公開はdevflowの公開ゲートに従って別途行う。

## 受け入れ条件

1. 既存のBMP選択、ファイルドロップ、一覧クリア、PNG変換が使える。
2. PNG圧縮レベル0〜9を設定でき、初期値9が適用される。
3. 一覧をドラッグまたは上下ボタンで並べ替えでき、変換順・PDFページ順に反映される。
4. PDFチェックなしでPNGだけを作成できる。チェックありではPDF名を指定でき、保存場所を選んでPDFを作成できる。
5. PNGをすべて先に作り、成功時にだけ単一PDFを生成する。
6. PDFは一覧順に1画像1ページ、A4で作成され、比率と元PNGピクセルの解像度を保ち、切り抜かない。
7. PDFの初期表示がページ全体表示かつ単ページ表示になる。
8. 変換失敗を明示し、成功済みPNGを残し、部分PDFを作らない。
9. Windows x64向けの配布物は、利用者側にPythonやネット接続がなくても起動する。
10. READMEに日本語の利用・開発・ビルド手順を記載する。リポジトリに生成物やローカル固有パスを含めない。
